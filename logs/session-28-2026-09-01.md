# Session 28 — 2026-09-01

## Topic
Implementing `list`, `mylistings`, `bin`, and `auction` commands, and standardising the
listing display format.

## Prompts
- Asked to handle `list` and `mylistings`.
- Noted there was no way to test these without `bin`/`auction`; asked to implement those too.
- Asked for error messages to reference the actual slash argument (e.g. `/desc`, `/price`).
- Noted the created-message and list-message formats were inconsistent; asked to standardise
  to `[uuid]: name` in the list view.
- Asked to make auction end times reject date-only input (require a time component).
- Asked to commit.

## Actions
- Implemented `list`: retrieves active listings, formats each as `[BIN/AUC] [uuid]: Name\ndesc\nprice`.
- Implemented `mylistings`: same format but includes all states (active, inactive, sold) for the
  current user, with state shown.
- Implemented `bin <name> /desc <description> /price <price>`: validates seller status,
  parses DESC/PRICE arguments, requires non-blank name and description, generates a 4-byte
  hex UUID via `SecureRandom`, adds a `BinListing`.
- Implemented `auction <name> /desc <description> /price <basePrice> /end <datetime>`: same
  validation; added date-only rejection using `DateTimeParser.parseDate` to detect and refuse
  inputs without a time component; checks end time is in the future.
- Error messages for missing slash arguments now reference the argument name explicitly,
  e.g. "Please provide a value for /desc."
- `generateUuid()` loops until a UUID is not already in the store.
- Added `MarketplaceTest` cases for bin and auction covering: successful creation, listing appears
  in `list`, missing fields, invalid price, not-a-seller, past end time, date-only end time,
  invalid end format.
- Committed implementation and tests.

## Outcome
Listings can be created and browsed; the display format is consistent; date-only auction end
times are rejected with a helpful error; all JUnit tests pass.

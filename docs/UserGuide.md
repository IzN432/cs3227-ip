# Ekko User Guide

Ekko is a desktop marketplace where users buy and sell items with coins through short chatbot commands.

## Quick start

1. Install **Java 25** and check it by running `java -version` in a terminal.
2. Place `ekko.jar` in a folder where Ekko may create its `data` folder.
3. Open a terminal in that folder and run `java -jar ekko.jar`.
4. Select **Create account**, enter a username and matching non-blank passwords, and submit the form.
5. Try `topup 100`, followed by `list`.

The username is case-sensitive and must be unique. Ekko stores a hash of the password rather than the
plain-text password. Use **Log out** to return to the sign-in screen without closing the application.

## Using the interface

Type one command in the field at the bottom, then press **Enter** or select **Send**. Input is briefly
disabled while Ekko processes the command. Expand **Command reference** for an in-app syntax summary.
Click any conversation bubble to copy its text to the clipboard.

Your command history, replies, and notifications are saved per account and restored at the next sign-in.
The balance shown in the upper-right corner updates after each command.

## Command conventions

- Command words are lowercase and case-sensitive.
- Replace placeholders such as `<uuid>` and `<price>` with values; do not include the angle brackets.
- Prices and coin amounts are positive whole numbers.
- Listing names and descriptions are required. Each recognised slash argument may appear only once.
- Listing identifiers are eight-character hexadecimal strings generated by Ekko, for example `7fa21b0c`.
- Search matching is a case-sensitive substring match.

### Auction date and time

Auction end times must be in the future and must include a time.

| Format | Example |
| --- | --- |
| ISO date and 24-hour time | `2026-09-02 1800` |
| Day-first date and 24-hour time | `2/9/2026 1800` |
| ISO date-time | `2026-09-02T18:00` |

Dates must exist in the calendar. Ekko displays a date-time such as `Sep 02 2026, 6:00 PM`.

## Accounts and coins

### Become a seller: `becomeseller`

Grants the signed-in account seller status. Every new account begins as a buyer; seller status is required
to create listings and remains active in future sessions.

**Format:** `becomeseller`

### Add coins: `topup`

**Format:** `topup <amount>`

**Example:** `topup 500`

### Withdraw coins: `withdraw`

Removes coins from your balance. The amount cannot exceed the available balance.

**Format:** `withdraw <amount>`

**Example:** `withdraw 50`

### Check your balance: `balance`

**Format:** `balance`

## Selling

### Create a fixed-price listing: `bin`

Creates an active Buy It Now (BIN) listing and returns its UUID.

**Format:** `bin <name> /desc <description> /price <price>`

**Example:** `bin Mechanical keyboard /desc Barely used, blue switches /price 80`

### Create an auction: `auction`

Creates an active auction. The starting bid and end date-time are required.

**Format:** `auction <name> /desc <description> /price <starting bid> /end <date/time>`

**Example:** `auction Film camera /desc Working condition /price 120 /end 2026-09-02 1800`

### View your listings: `mylistings`

Shows all listings you own, including active, sold, and inactive listings. Each result includes its state.

**Format:** `mylistings`

### Delete a listing: `delete`

Deletes one of your active listings. You cannot delete another user's listing, a completed listing, or an
auction whose end time has passed. If an active auction has a highest bid, deletion refunds and notifies
that bidder.

**Format:** `delete <uuid>`

**Example:** `delete 7fa21b0c`

## Browsing and buying

### Browse listings: `list`

Shows every active BIN and auction listing. BIN results show their fixed price; auctions show the current
highest bid, or the starting bid when no bid exists.

**Format:** `list`

### Find listings: `find`

Searches active listing names and descriptions. Optional inclusive price bounds apply to the fixed BIN
price or an auction's current bid (starting bid when it has no bids). Either bound may be omitted.

**Format:** `find <keyword> [/low <minimum>] [/high <maximum>]`

**Examples:** `find camera`, `find camera /low 50 /high 200`, `find camera /high 150`

### Buy a fixed-price listing: `buy`

Immediately buys an active BIN listing. You need enough coins and cannot buy your own listing. Ekko
deducts the buyer, credits the seller, marks the listing sold, and notifies the seller.

**Format:** `buy <uuid>`

**Example:** `buy 7fa21b0c`

### Bid on an auction: `bid`

Places a bid on an active auction. The first bid must meet the starting bid; later bids must exceed the
current bid by at least one coin. You cannot bid again while already winning.

Ekko deducts the bid immediately. When another user outbids you, your earlier bid is refunded and a
notification is added to your conversation.

**Format:** `bid <uuid> /price <amount>`

**Example:** `bid 7fa21b0c /price 135`

### View purchases: `mypurchases`

Shows fixed-price purchases and auctions you have won.

**Format:** `mypurchases`

## Auction completion and notifications

Ekko checks for ended auctions approximately once per second while the application is running.

- An auction with bids is marked sold. The seller receives the winning bid, and both seller and winner
  receive conversation notifications.
- An auction without bids becomes inactive, and the seller receives a notification.
- Notifications are stored even when the affected user is signed out and appear in that user's history
  after the next sign-in.

## Ending a session

`bye` ends the current marketplace session and disables further commands. Close the window to exit.
To switch accounts without ending the application, use the **Log out** button instead.

## Saving and recovery

Ekko saves data automatically under `data`, relative to the folder from which it is launched:

- `data/users.txt` stores accounts, seller status, password hashes, and balances.
- `data/listings.txt` stores all active and completed listings and bids.
- `data/conversations/<user-uuid>.txt` stores each account's conversation history and notifications.

Shared marketplace data is saved after every command. Writes use a temporary file before replacing the
destination to reduce the risk of partial data. Close Ekko before copying the `data` folder as a backup.

If `users.txt` or `listings.txt` is unreadable or invalid, Ekko reports a startup error, leaves the files
unchanged, and exits. If one conversation file is damaged, only that history is replaced with a recovery
message; the account and marketplace data remain available.

## Troubleshooting

- **Invalid username or password:** Usernames and passwords are case-sensitive; retry or create an account.
- **Unknown command or missing value:** Compare the command with **Command reference** or the formats above.
- **Insufficient balance:** Use `balance` to check the balance and `topup` to add test coins.
- **Listing unavailable:** Run `list` again. It may have been bought, deleted, or resolved after its end time.
- **Saved data error:** Back up the `data` folder before inspecting it. Ekko will not overwrite invalid shared data.
